# memory-save — 기억 저장소에 남기기

세션에서 얻은 결정·함정·다음 할 일을 이 폴더의 기억 은행에 남겨, 다음 세션이 시작 컨텍스트로 이어받게 하는 스킬이다. 네 가지 모드가 있다.

| 호출 | 언제 | 저장 종류 |
|---|---|---|
| `/memory-save` | "세션 종료" 뒤 인계문(기본) | `--kind handoff` |
| `/memory-save note <내용>` | "기억해", 또는 자동 중간 저장 기준에 걸릴 때 | `--kind note` |
| `/memory-save forget <대상>` | "잊어줘" | 삭제 |
| `/memory-save correct <대상> → <새 내용>` | "정정해" | `--kind correction` 저장 뒤 옛 기억 삭제 |

## 공통 준비

1. 세션 시작 컨텍스트의 "기억 저장소 (Hindsight)" 절에서 "이 폴더의 은행"과 "저장 토큰"을 찾아 쓴다.
2. 그 절이 없거나 저장 토큰이 없으면(세션 시작 훅이 안 돌았거나 카드 없는 폴더), 또는 토큰 자리에 "저장 불가"라고 적혀 있으면 저장하지 않고 사용자에게 한 줄로 알린다. 예: "이 세션에는 저장 토큰이 없어 기억을 저장하지 않았습니다."
3. 명령은 항상 전체 경로 `~/.claude/scripts/hindsight-mem`으로 부른다.
4. 저장·삭제는 주 세션이 직접 실행한다. 보조 에이전트에게 토큰을 넘기거나 저장·삭제를 시키지 않는다. 보조 에이전트에게 맡긴 결과를 저장할 때도 본문만 받아 주 세션이 실행한다.
5. **저장 금지**: 실명, 주민번호, 급여, 연락처, 후보자 정보, 토큰·키·비밀번호는 본문에 쓰지 않는다. 필요한 맥락은 역할명("채용 담당자", "후보자 A")이나 파일 경로로 대신한다.
6. 개인정보 카드 폴더(카드에 `sensitive: pii`. 시작 컨텍스트에 "개인정보를 다루는 폴더" 주의가 붙는다)에서는 위 금지 항목을 요약·가명으로도 쓰지 않는다. 사람이 아니라 결정과 절차만 남긴다.

## 인계문 모드 (기본, `/memory-save`)

1. 같은 턴에 PROGRESS·PLAN 같은 진행 문서를 정리했다면(별도 `session-end` 스킬을 쓴다면 그 결과) 그 내용을 바탕으로, 없으면 이번 대화에서 직접 추려 쓴다.
2. 아래 **세 항목만**, 소제목 그대로, 한국어 산문으로 쓴다. 전체 분량은 300~1,500자를 기준으로 한다(조정 가능).

   ```
   ## 결정과 이유
   (이번 세션에 정한 것과 그렇게 정한 까닭. 버린 대안이 있으면 한 줄)

   ## 함정과 배운 것
   (헛걸음한 곳, 다시 겪지 않으려면 알아야 할 것)

   ## 남은 일과 다음 첫 행동
   (남은 일, 그리고 다음 세션이 어느 파일·어떤 명령부터 시작할지)
   ```

3. 저장 금지 항목이 들어가지 않았는지 다시 훑는다.
4. 본문을 프로젝트 밖 임시 파일에 쓰고 저장한 뒤 임시 파일을 지운다.

   ```bash
   tmp=$(mktemp -t memory-save)
   # 본문을 "$tmp"에 쓴다
   ~/.claude/scripts/hindsight-mem retain --kind handoff --token <토큰> "$tmp"
   rm -f "$tmp"
   ```

5. 표준 출력에 나온 식별자(예 `budget-book-20261016-153012-1a2b3c4d`)를 사용자에게 한 줄로 보고한다.
6. 표준 오류에 "임시 보관" 문구(예 "기억 저장소에 닿지 못해 임시 보관했습니다: …")가 나오면 그 문구를 그대로 전하고, 다음 세션 시작 때 자동으로 다시 보낸다고 알린다. 이 경우 종료 코드는 0이며 식별자는 나오지 않는다.

## 중간 저장 (`/memory-save note <내용>`)

- 사용자가 "기억해"라고 하면 쓴다. 사용자가 말하지 않아도 다음 세 기준 중 하나에 걸리면 에이전트가 스스로 쓴다: **설계를 바꾸는 결정, 되돌리기 어려운 선택, 재현하기 어려운 함정.** 일상 진행 상황은 저장하지 않는다.
- 본문은 한두 문단. 무엇을 정했는지(또는 무엇에 걸렸는지)와 이유를 쓴다.
- 저장 방법은 인계문 모드 4~6단계와 같고 종류만 다르다.

  ```bash
  ~/.claude/scripts/hindsight-mem retain --kind note --token <토큰> "$tmp"
  ```

## 삭제 (`/memory-save forget <대상>`)

1. 대상이 식별자(예 `budget-book-20261016-…` 꼴, `<은행>-<날짜>-<시각>-<세션>`)면 바로 지운다.

   ```bash
   ~/.claude/scripts/hindsight-mem forget <식별자> --token <토큰>
   ```

2. 대상이 자연어면 먼저 찾는다.

   ```bash
   ~/.claude/scripts/hindsight-mem recall "<대상>"
   ```

   출력 줄은 `- <내용> (<시각>, <식별자>)` 꼴이다. 후보 식별자와 본문 요약을 사용자에게 보여 주고, **어느 것을 지울지 사용자 확인을 받은 뒤** 1단계로 지운다. 확인 없이 지우지 않는다. 후보가 없으면("관련 기억이 없습니다") 그대로 알리고 끝낸다.
3. 성공하면 "삭제했습니다: <식별자> (은행 <은행>)" 줄을 그대로 전한다.

## 검색할 때

- `recall`의 질의는 "남은 일", "결정" 같은 항목 이름이 아니라 **내용 단어**로 쓴다(예: `recall "DNS 레코드 추가"`). 저장소가 사실을 추출하면서 항목 이름은 사라진다.
- 같은 이유로 인계문의 문장은 "DNS 레코드 추가가 남아 있다"처럼 항목 이름 없이도 뜻이 통하게 쓴다.

## 정정 (`/memory-save correct <대상> → <새 내용>`)

1. 옛 기억의 식별자를 확정한다(자연어 대상이면 삭제 절차 1~2처럼 후보를 보여 주고 사용자 확인 필수).
2. **먼저** 새 내용을 본문 첫 줄에 `정정: <옛 식별자> 대체`를 넣어 저장한다(저장이 실패하면 옛 기억은 지우지 않고 멈춘다 — 대체 없이 사라지는 일을 막는다).

   ```bash
   ~/.claude/scripts/hindsight-mem retain --kind correction --token <토큰> "$tmp"
   ```

3. 저장이 성공했을 때만 옛 기억을 지운다.

   ```bash
   ~/.claude/scripts/hindsight-mem forget <옛 식별자> --token <토큰>
   ```

4. 새 식별자와 삭제 결과를 한 줄로 보고한다.

## 실패 처리

종료 코드별로 사용자에게 한 줄로 알린다.

| 종료 코드 | 뜻 | 안내 |
|---|---|---|
| 4 | 주 세션의 토큰이 아님 | "저장 토큰이 이 세션 것이 아니어서 저장하지 않았습니다." 시작 컨텍스트의 토큰을 다시 확인한다. 보조 에이전트에서 실행했다면 주 세션에서 다시 한다. |
| 2 | 은행 이름 문제(허용 목록 밖) | 표준 오류의 문구를 그대로 전한다. 은행을 임의로 지정해 다시 시도하지 않는다. |
| 3 | 이 폴더는 기억 대상이 아님 | "이 폴더는 기억 저장 대상이 아닙니다." |
| 1 | 그 밖의 실패(본문 비어 있음, 삭제 실패 등) | 표준 오류의 문구를 그대로 전한다. |

어떤 경우에도 기억 저장 실패가 세션 작업을 막지 않는다. 한 줄로 알리고 하던 일을 이어 간다.
